# Bounded maintenance

Run daily at 10:00 Asia/Shanghai; Saturday uses the same schedule for a weekly review. Daily budget about 20 minutes, weekly about 45; stop earlier when there is no useful task. Extra paid budget is zero. Preserve the Owner's configured model and reasoning.

The shared private state is `.maintenance` beside the common Git directory of the canonical checkout. `scripts/maintenance.py` validates a private registry, acquires a nonblocking OS lock, records run ID/PID/process creation/start, checks the registered worktree and preserves all owner diffs. Lock contention returns SKIPPED_ALREADY_RUNNING. The persistent lock file is never deleted; the operating system releases the actual lock when its process exits, so no stale PID deletion is needed. Unknown lock state is a failure, never a reason to kill a process. State and receipts are excluded from Git and distributions.

Before enabling a schedule, register the canonical root and permitted dedicated worktree in `.maintenance/repository.json`, then manually run the exact prompt below, including the runner. The runner is a bounded local inspection/check component, not an autonomous code-editing or hosting service. Codex must inspect the resulting status/backlog and execute any evidence-based task itself under the same lock. Use `--guard` to hold the lock while doing the full Codex session: the runner waits on its input; send a JSON completion receipt on stdin only when the session finishes. `--verify` performs local tests and exits for deterministic rehearsal. Lock acquisition does not authorize public actions.

## Scheduled prompt

Read AGENTS, MAINTENANCE, the last private state, current HEAD and worktree diffs. Use only this repository and its private registry's dedicated worktree. Start `scripts/maintenance.py --guard` in a persistent terminal using the registered worktree and a verified project Python. Keep its process/input open until the whole run completes; if the guard exits early, stop changes and reconcile. A held lock means SKIPPED_ALREADY_RUNNING; never overlap. Confirm its PID/start record. Preserve owner changes; do not reset, clean or directly edit the canonical checkout.

Use Asia/Shanghai date: Saturday is weekly review within this same task; other days incremental. Before publication, inspect local backlog; after publication, read issues/PR/CI only where access is authorized. Pick one useful task from actual evidence. Prioritize reproducible failures, then installation/docs problems, then already requested small changes. Do not invent community activity or work merely to commit. Changes stay in the dedicated branch; create a local reviewable diff if continuous remote permission is absent. Do not merge external PRs, publish versions, change visibility or speak for the Owner without authorization.

Run risk-appropriate tests and preserve core contracts. Weekly also build/install smoke, review relevant dependency/security signals and examples, and summarize actual links if available. Monthly recheck supported systems, licenses, direction and current official application rules when relevant. No repeated broad scans, automatic dependency upgrades or evidence deletion. Same external block in two consecutive runs becomes WAITING_EXTERNAL with a resume condition; continue other safe work.

Do not touch production, proxy, DNS, services, global skills or secrets; no paid APIs/GPU. Keep COS IMPLEMENTED_UNVERIFIED until actual service evidence. Report status, base/result commit, actual changes/tests, NOT_RUN, exact blockers and next step in private state. Send the guard a JSON object containing status, summary, tests, blockers and next; verify its exit and receipt. NO_CHANGE is valid. Stay quiet for unchanged or non-actionable state; notify only meaningful change, completion, failure or necessary Owner action.
